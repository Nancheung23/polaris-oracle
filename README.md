# 🔮 Polaris Oracle

**Your fortune, written in code and stars.**

A Web3 divination dApp that combines a Solana on-chain ticketing economy with an AI-generated Zi Wei Dou Shu (紫微斗数 / Purple Star Astrology) reading engine. Connect a wallet, pay in `$POT` tokens, and receive a multi-section natal chart analysis grounded in classical Chinese astrology and generated by a chained series of LLM calls.

Built for **Solana Summer School 2026**.

Live: [polaris-oracle.xyz](https://polaris-oracle.xyz)

---

## What it does

1. **Connect a Solana wallet** (devnet/testnet) — no traditional signup required. A wallet address _is_ the user identity.
2. **Buy a ticket** with `$POT`, the platform's SPL token. Each purchase burns a configurable percentage of the token and sends the rest to a team vault, recorded on-chain.
3. **Submit birth details** (name, gender, birth date, birth hour/_shichen_, location).
4. **Consume the ticket** on-chain, which is verified server-side against the transaction signature before any AI work happens.
5. **Get a reading**, computed in two stages:
   - A natal chart (astrolabe) is calculated locally using the `iztro` library.
   - The chart data is fed through a chain of **11 Claude Haiku calls** (core analysis → life topics → summary → 8 parallel decade-by-decade timelines), paid for via the **x402** protocol so each AI call is itself a micropayment on Solana.
6. Reports are persisted in MongoDB and rendered as a shareable page.

## Architecture

This is a two-part monorepo:

```
polaris-oracle/
├── programs/anchor/     # Solana on-chain program (Rust / Anchor)
├── migrations/          # Anchor deploy script
├── Anchor.toml
└── web/                 # Next.js 16 frontend + API routes
    ├── app/              # App Router pages & API routes
    ├── components/       # UI components (shadcn/ui + Base UI)
    ├── lib/              # Business logic (AI, Solana, iztro, models)
    └── hooks/            # React hooks for wallet/ticket/report state
```

### On-chain program (`programs/anchor`)

An Anchor program that manages the platform's token economy:

| Instruction                                                                                   | Purpose                                                                                                                                                          |
| --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `initialize`                                                                                  | Sets up the `PlatformState` PDA — price, burn rate, operator, airdrop config.                                                                                    |
| `buy_ticket`                                                                                  | User transfers `$POT` to the platform. A configurable % is burned via SPL `Burn`, the rest goes to the vault. Creates a `UserState` PDA on first purchase.       |
| `consume_ticket`                                                                              | Decrements the user's ticket balance and mints an incrementing on-chain `order_id`, used later to verify the reading request came from a real, paid transaction. |
| `airdrop`                                                                                     | Operator-gated reward: users who cross a configurable `total_service` threshold become eligible for a `$POT` airdrop from a capped budget.                       |
| `withdraw`                                                                                    | Admin withdraws accumulated vault funds.                                                                                                                         |
| `update_platform_state` / `pause_platform` / `update_airdrop_requirement` / `update_operator` | Platform admin/operator controls.                                                                                                                                |

State is tracked in two PDA account types:

- **`PlatformState`** — global config + running statistics (`total_consume`, `total_service`, `total_burnt`).
- **`UserState`** — per-wallet ticket balance, personal consumption stats, and the on-chain `order_id` counter used for reading verification.

### Web app (`web/`)

**Stack:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · shadcn/ui + Base UI · MongoDB/Mongoose · Solana Wallet Adapter · x402

**Key flows:**

- **Wallet-based identity** — `@solana/wallet-adapter-react` replaces traditional auth. A connected wallet address is the only identity primitive.
- **Ticket-gated reading flow** (`app/reading/new`) — `TicketGate` checks the user's on-chain `UserState` before allowing the form to be submitted; `useConsumeTicket` sends the `consume_ticket` instruction and returns the transaction signature.
- **Server-verified generation** (`app/api/generateReport`) — before any AI cost is incurred, the server re-verifies the submitted `txSignature` against the chain (`verifyConsumeTicketTx`) and cross-checks the latest on-chain `order_id`, preventing spoofed or replayed requests.
- **AI report pipeline** (`lib/ai/generateReportContent.ts`) — runs _after_ the ticket is confirmed and the report record is created, using Next.js `after()` so the HTTP response returns immediately while generation continues server-side:
  1. Natal chart computed via `iztro` (`getAstrolabe`, `summarizeAstrolabeForAI`, `getDecadeTimelines`).
  2. **Call 1** — core personality/life analysis.
  3. **Call 2** — topic breakdown (health, study, business, money, relationship, marriage).
  4. **Call 3** — plain-language summary + disclaimer.
  5. **Calls 4–11** — one decade-by-decade timeline narrative per life decade, run in parallel via `Promise.all`.
  6. Each call is billed individually through `@x402/fetch`, and per-call token cost is tracked and logged.
- **Persistence** — `Report` and `User` Mongoose models in MongoDB; report status moves `pending → completed | failed` as background generation resolves.
- **Ambient audio** — background music is streamed from a Cloudflare R2 bucket, toggled via a fixed play/pause button (no volume control — silent by default).

## Getting started

### Prerequisites

- Node.js + Yarn
- Rust toolchain + [Anchor CLI](https://www.anchor-lang.com/docs/installation)
- A Solana wallet (Phantom recommended) funded with devnet/testnet SOL and the `$POT` test token
- A MongoDB instance

### On-chain program

```bash
# from repo root
yarn install
anchor build
anchor test        # runs the Rust test suite under programs/anchor/tests
anchor deploy       # deploys to the cluster configured in Anchor.toml
```

### Web app

```bash
cd web
npm install
```

Create `web/.env.local` with:

```bash
MONGODB_URI=your_mongodb_connection_string
ADMIN_WALLET_SECRET_KEY=your_admin_wallet_secret_key
# mainnet wallet with sufficient balance
X402_PROJECT_WALLET_SECRET_KEY=your_x402_wallet_secret_key
X402_PROJECT_WALLET_ADDRESS=your_x402_wallet_address
# cloudflare R2 (optional)
NEXT_PUBLIC_AUDIO_BASE_URL=https://your-r2-audio-domain
```

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

### Useful scripts (`web/scripts`)

The repo includes 21 standalone diagnostic scripts (run with `npm run <script>`), used during development to test each pipeline stage in isolation — e.g. `testIztro`, `testOrderId`, `testX402CoreAnalysis`, `testGenerateReport`, `checkMintAuthority`. See `web/package.json` for the full list. (need tsx)
